# 回复整形（astrbot_plugin_reply_trim）

把机器人的一条回复整理成**更像真人聊天**的样子：

- 去掉首尾多余的空白与换行
- 按「。？！」与换行把长回复拆成几条，间隔一小段随机时间依次发出
- 模型换行＝想单独发一条；只有**实字 ≤ `tail_merge_len`** 的极短行（「唔……」「哼…」）并到**下一条的前面**
- 括号里的动作描写并到**后面那句台词的前面**
- 模型夹带的花括号状态标记（如 `{mood: happy}`）不发给用户

> 全部是本地规则，**不调用任何模型**，不增加 token 消耗。

---

## 一、首尾去空白

QQ 群里机器人气泡文字前面经常多出一块空白，原因是两个叠在一起：

1. **LLM 自己吐的换行** —— 实测约 61% 的回复开头带 2~4 个换行，在人格提示词里写「不要空行」并不可靠
2. **AstrBot 加的换行** —— 开启 `platform_settings.reply_with_mention` 时，`result_decorate/stage.py` 会在 @ 之后插入一个换行

AstrBot 没有内置的「清理回复首尾空白」开关（`content_cleanup_rule` 只属于分段回复），本插件在发送前统一 trim 掉。

## 二、分段发送

| 规则 | 默认 | 说明 |
|---|---|---|
| `split_chars` | `。？！` + 换行 | 在这些字符**后面**切段；换行是硬边界，永远不合并 |
| `drop_chars` | `。！` | 每条消息**末尾**的符号删掉；问号不在其中所以保留 |
| `line_split_min_len` | 24 | 一行短于这个长度就整行发出，不再按标点切碎 |
| `min_segment_len` | 6 | 同一行内按标点切出来的碎片，太短的并到下一段 |
| `tail_merge_len` | 3 | 「实字」不超过这个数的极短行并到下一条；调大＝更多行被合并，调小＝更倾向拆开 |
| `max_segments` | 6 | 最多几条，超出的合并到最后一条 |
| `segment_delay_min/max` | 0.7 / 1.2 | 条与条之间随机等待（秒），模拟打字节奏 |

### 合并规则举例

| 模型输出 | 实际发出 |
|---|---|
| `哼...` / `不理你了` | `哼...不理你了`（一条） |
| `今天好累...` / `晚安...` / `好梦...` | `今天好累...` ＋ `晚安...好梦...`（两条） |
| `好啦...` / `过来一点...` / `勉强……再夸你两句总行了吧` | `好啦...过来一点...` ＋ `勉强……再夸你两句总行了吧` |
| `……唔……` / `……啾……` / `……嗯……` / `……好啦……够了吧……` | `……唔…………啾…………嗯…………好啦……够了吧` ＋ 若末尾还有 `……唔……` 再单发一条 |
| `（小声补充）` / `……那我先走了，你早点休息` | `（小声补充）……那我先走了，你早点休息`（动作 + 台词） |
| `……晚安` / `好梦` / `【害羞】{mood: happy}` | `……晚安好梦【害羞】`（状态标记被删掉） |

### 保护规则

| 配置 | 默认 | 作用 |
|---|---|---|
| `protect_code` | 开 | 检测到代码块 / 列表 / 引用 / 表格时整条不分段 |
| `protect_quotes` | 开 | 引号、括号内部不切段，避免「前引号在上一句、后引号在下一句」 |
| `min_text_len` | 0 | 整条太短（且无换行）就不分段；0 = 不设门槛 |

### 群聊 / 私聊 / 黑名单

- `group_split_enable`：群聊里也分段（默认开）
- `private_split_enable`：私聊里也分段（默认开）
- `blacklist`：不分段的会话，填 **群号 / 用户号 / 完整会话标识**（如 `aiocqhttp:GroupMessage:12345`），命中的会话照常回复、只是不分段

### 私聊「正在输入」

补发下一段前，先通过 OneBot 扩展动作 `set_input_status` 把机器人设为「正在输入」，**再**随机等一会儿 —— 对方看到的是「正在打字」然后消息冒出来。

- `typing_enable`（默认开）、`typing_event_type`（默认 1）
- **只对私聊有效**：LLOneBot 底层是 `setPrivateInputStatus`，群聊没有这个能力，插件自动跳过
- 调用失败只记 DEBUG 日志，绝不影响正常发送

## 三、安装

1. AstrBot WebUI → 插件 → 从仓库安装：`https://github.com/q1w2e3r4t5y6658/astrbot_plugin_reply_trim`
2. 或手动把本目录放到 `AstrBot/data/plugins/astrbot_plugin_reply_trim/`，重启 AstrBot

> ⚠️ 如果 AstrBot 配置里设置了 `plugin_set`（插件白名单，不是 `["*"]`），必须把
> `astrbot_plugin_reply_trim` 加进该名单，否则本插件的钩子不会被调用（静默失效）。

## 四、只对纯文本的模型回复生效

带图片、@、引用等组件的回复链**整条不动**，不会把消息结构拆坏。

## 五、看日志

默认只打 DEBUG 日志。在 AstrBot WebUI 的插件页把本插件日志级别调到 DEBUG，即可看到每次分段的结果。

## 六、常见问题

**Q：为什么有时候不分段？**
A：整条只有一句、或含代码块/列表、或命中了黑名单、或剩下的段数不足 2 条，都会保持原样。

**Q：为什么气泡里出现了换行？**
A：那是模型自己写的换行（换行被视为它想分条的信号），可以在人格提示词里要求它不要在多行里换行。

**Q：想让它拆得更碎 / 更整？**
A：调 `line_split_min_len`（越小越容易切）与 `min_segment_len`（越大越容易合并）。
